**Öneri**

A) **Screen Space Overlay, tek statik Canvas**
Win/Fail/HUD için prefab pool kullanma. Bu UI runtime’da sık spawn/despawn edilen gameplay unit değil; tek `GameFlowView` / `HudView` Canvas daha temiz.

Best practice:
- `Canvas` = Screen Space Overlay
- `WinPanel`, `FailPanel`, `LevelText` serialized refs
- DOTween ile `CanvasGroup.DOFade`
- Butonlar Inspector’dan değil, controller init içinde explicit bind

Trade-off: World Space Canvas 3D sahneyle daha bütünleşik görünür ama mobil puzzle UI için çözünürlük/safe area/overlay davranışı Screen Space Overlay’de daha stabil.

B) **Evet, `GameFlowController` ayrı MonoBehaviour**
[[script:Assets/_Game/_Scripts/Features/BlockJam/GameplayCompositionRoot.cs:12|GameplayCompositionRoot:12]] zaten level build, input response, animation orchestration, pool wiring yapıyor. Win/fail/save/HUD eklemek root’u fazla büyütür.

Somut ayrım:
- `GameplayCompositionRoot`: level yükler, core session çalıştırır, visual animation tamamlanınca event/callback verir.
- `GameFlowController`: current level index, continue/retry, save/load, overlay aç/kapat.
- `HudView`: level index text.
- `EndGameOverlayView`: win/fail panel API.

C) **persistentDataPath + JSON + temp→rename**
PlayerPrefs MVP’de hızlı ama save schema büyüyünce kötüleşir. Burada zaten “local save/load” Faz 5 kapsamı; doğru temel at.

Öneri:
```csharp
[Serializable]
public sealed class BlockJamSaveData
{
    public int CurrentLevelIndex;
}
```

`Application.persistentDataPath/blockjam_save.json` yaz.
Akış:
1. JSON serialize
2. `.tmp` dosyasına yaz
3. varsa eski save’i sil/backup
4. tmp → final rename/move

Best practice: Atomic write MVP’de de değerli; kodu küçük, mobilde yarım yazılmış save riskini azaltır.

D) **Continue → clamp/wrap ile `LoadLevel(currentIndex + 1)`**
Evet, ama direkt index artırma yerine sınır davranışını netleştir.

Öneri:
```csharp
next = current + 1;
if (next >= levelCount)
    next = 0; // veya last level ekranı
```

Sonra:
- `_currentLevelIndex = next`
- save
- overlay kapat
- root’a `LoadLevel(next)` çağır

Bunun için [[script:Assets/_Game/_Scripts/Features/BlockJam/GameplayCompositionRoot.cs:86|GameplayCompositionRoot.LoadLevel:86]] `private` kalmamalı; `public void LoadLevel(int levelIndex)` veya `GameFlowController`’ın çağıracağı dar bir API olmalı. `Restart()` şu an `Initialize()` ile hep level 0’a dönebilir; current index destekleyecek şekilde değişmeli.

E) **Basit enum state, bool değil**
Bool flag kısa vadede yeter gibi görünür ama `Animating`, `Overlay`, `Loading` ayrımı hemen gerekiyor.

Öneri:
```csharp
private enum GameplayInputState
{
    Ready,
    Animating,
    OverlayOpen,
    Loading
}
```

Tap guard:
- `Ready`: tap işlenir
- `Animating`: ignore
- `OverlayOpen`: ignore
- `Loading`: ignore

Invalid tap feedback sadece `Ready` durumunda çalışsın. Match animasyonu sırasında hiçbir tap alınmasın. Overlay açıkken sadece UI button çalışsın.

Invalid tap için:
- [[script:Assets/_Game/_Scripts/Features/BlockJam/GameplayCompositionRoot.cs:133|OnUnitTapped:133]] başarısız result aldığında `UnitView` bulunursa `transform.DOShakePosition(...)`
- Shake ayarlarını [[script:Assets/_Game/_Scripts/Features/BlockJam/AnimationConfigSO.cs:7|AnimationConfigSO:7]] içine ekle:
```csharp
public float InvalidShakeDuration = 0.18f;
public float InvalidShakeStrength = 0.08f;
public int InvalidShakeVibrato = 12;
```
- SFX placeholder için `AudioSource` serialized ref veya şimdilik `Debug.Log("[SFX] InvalidTap")`.
